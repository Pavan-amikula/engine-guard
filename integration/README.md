# Model-based integration handoff

## Interface and scheduling

Call `eg_init(&state)` once at startup, then `eg_step(&state, inputs, measured_pressure)` at nominal 50 ms intervals. One state belongs to one independent engine instance. The sample interval is derived from the benchmark; the recorded time has small jitter. The monitor coefficients and one-sample input delay assume this rate. Do not reuse them unchanged at a different rate. The function has no allocation, I/O or mutable global state.

Input order is `[air_mass_flow, engine_speed, Intercooler_pressure, throttle_position, intercooler_temperature, wastegate_position]`. Pressure is Pa, temperature K, speed rad/s, airflow kg/s. Throttle and wastegate retain the source encoding; confirm calibration mapping before use with another dataset or ECU. No fuel input is required. A status of 2 means the pressure output is unavailable if physical inputs were invalid; downstream logic must check status before using it. Status 1 means a clipped speed-density fallback. Status 0 enables the diagnostic monitor. Fallback is a demonstration policy, not an approved engine-control safety strategy.

## Simulink

`build_simulink_harness.m` prepares a 0.05 s fixed-step C Caller inference harness using `eg_predict`. Run it from MATLAB after model generation. It supplies a constant golden input and configures custom C includes/sources. This script was not executed in the delivered environment. Use `eg_predict` only after validating physical inputs and constructing 13 causal features: six current signals, six previous signals, and `mass_flow*temperature/speed`.

For a full model, expose six inputs and measured pressure, maintain caller-owned `EgState`, and call `eg_step` using an S-function or supported custom-code wrapper. Compare a complete independent trace to `reports/demo_replay.csv`, including status and alarm channels. Verify reset, rate transition and subsystem enable/disable behavior. Generated model files are build products, not evidence of a completed MATLAB run.

## TargetLink

Use the installed version's documented external/custom-code mechanism. Import `engine_guard.h`, compile `engine_guard.c`, and add `model_data.h` on the include path. Map single precision to a verified 32-bit IEEE representation; preserve int16 coefficient storage. Keep model constants in read-only calibration/code memory according to the ECU linker configuration. Register each instance's state explicitly. Do not assume a Simulink C Caller block can be directly code-generated by TargetLink.

The supplied artifact is a handoff, not a tested TargetLink model. Acceptance requires: host back-to-back comparison, licensed-tool SIL comparison to golden vectors, target PIL error checks, linker map RAM/flash measurements, stack measurement under the target compiler, cycle-count timing with interrupts and caches accounted for, scheduling margin, and calibration/fault-injection review. Vendor-specific data-dictionary and block APIs are intentionally not guessed.

## Numerical and maintenance contract

Weights are quantized to int16 with one scale per layer, then multiplied using floating point. This reduces coefficient storage; it is **not integer-only inference**, and no integer-MAC speedup is claimed. `models/model.npz`, `embedded/model_data.h`, the source archive hash and the reported selected architecture form a traceable release. The deployed model is frozen before FTP75 evaluation. Keep `-ffast-math` off because finite-input handling is part of the contract. Future changes need replay, parity and fault-monitor re-evaluation.
